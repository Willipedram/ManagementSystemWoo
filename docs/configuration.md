# راهنمای پیکربندی و استقرار

این سند مراحل پیکربندی سامانه ManagementSystemWoo را برای محیط‌های توسعه، آزمایشی و تولید توضیح می‌دهد.

## فایل‌های پیکربندی مهم

| فایل | توضیح | نکات امنیتی |
|------|-------|-------------|
| `local_config.secure` | شامل اطلاعات اتصال به پایگاه داده ووکامرس (`db`) و پایگاه داده داخلی سامانه (`logdb`). این فایل در اولین اجرای ویزارد نصب تولید می‌شود. | از ذخیره فایل در مخازن Git یا مسیرهای قابل دسترس عموم خودداری کنید. دسترسی فایل را فقط به کاربر وب‌سرور محدود کنید. |
| `config.secure` | اطلاعات ورود مدیر سامانه و مجوزها. توسط `ajax.php` مدیریت می‌شود. | در صورت تغییر رمز مدیر سیستم، از ابزارهای مدیریت رمز امن استفاده کنید. |
| `chatgpt_config.json` | تنظیمات ادغام با ChatGPT (مدل، دمای پاسخ، کلید API رمزنگاری‌شده). | در محیط تولید ترجیحاً مسیر فایل روی دیسک رمزگذاری‌شده یا Storage امن قرار گیرد. |
| `dns_config.json` | تعریف پروکسی/سرورهای جایگزین برای عبور از محدودیت‌ها. | فقط در صورت نیاز به بروزرسانی و با رعایت سیاست‌های سازمانی دستکاری شود. |

## مراحل راه‌اندازی اولیه

1. **نصب پیش‌نیازها**
   - PHP 8.1 یا جدیدتر به همراه افزونه‌های `mysqli`, `curl`, `openssl`, `mbstring`, `dom`.
   - وب‌سرور (Nginx/Apache) با قابلیت اجرای PHP.
   - پایگاه داده MySQL یا MariaDB.

2. **کلون مخزن و نصب وابستگی‌ها**
   ```bash
   git clone <repository-url>
   cd ManagementSystemWoo
   composer install
   ```

3. **ایجاد پایگاه‌های داده**
   - یک پایگاه داده برای ووکامرس (در صورت عدم وجود) و یک پایگاه داده مجزا برای سامانه ایجاد کنید.
   - کاربر پایگاه داده با دسترسی لازم ایجاد و یا به‌روزرسانی شود.

4. **اجرای ویزارد نصب**
   - دامنه یا آدرس IP سرور را در مرورگر باز کنید.
   - مراحل سه‌گانه ویزارد (`index.php`) را تکمیل کنید: اتصال ووکامرس، اتصال پایگاه داده محلی، ساخت کاربر مدیر.
   - در صورت نیاز گزینه «گزارش اشکال‌زدایی نصب» را فعال کنید تا لاگ نصب در فایل `msw_debug.log` ذخیره شود.

5. **اعمال طرح پایگاه داده محلی**
   - در اولین اجرا، اسکریپت نصب به طور خودکار جداول تعریف‌شده در `schema.sql` را می‌سازد.
   - در صورت نیاز به ساخت دستی، فایل را اجرا کنید:
     ```bash
     mysql -u <user> -p <database> < schema.sql
     ```

## تنظیم کران و سرویس‌های پس‌زمینه

- اجرای برنامه‌ریزی‌شده فرایندها:
  ```bash
  # اجرای هر 15 دقیقه
  */15 * * * * /usr/bin/php /path/to/project/cron.php >> /var/log/msw-cron.log 2>&1
  ```

- پردازش صف‌ها:
  ```bash
  # اجرای دائمی یا از طریق Supervisor/systemd
  /usr/bin/php /path/to/project/worker.php
  ```

> پیشنهاد می‌شود برای `worker.php` از سرویس systemd با قابلیت Restart on failure استفاده شود.

## پیکربندی ChatGPT

1. در منوی تنظیمات سامانه، کلید API ارائه‌شده توسط OpenAI را وارد کنید.
2. `ChatGPTManager` کلید را با AES-256-CBC رمزنگاری و در `chatgpt_config.json` ذخیره می‌کند.
3. برای اطمینان از صحت تنظیمات، دکمه «تست اتصال» را فشار دهید. نتایج تست در فایل `chatgpt.log` ذخیره می‌شود.

## راه‌اندازی Google Search Console

برای فعال کردن همگام‌سازی خودکار داده‌های سرچ کنسول (فرایند `runGscFetch` در `ProcessManager`) تمام مراحل زیر را به‌ترتیب انجام دهید:

1. **پیش‌نیازها**
   - مالکیت دامنه یا مسیر سایت را در [Google Search Console](https://search.google.com/search-console) تأیید کنید و مطمئن شوید نوع مالکیت همان مقداری است که قصد دارید در سامانه وارد کنید (معمولاً URL-prefix یا Domain property).
   - کاربری که قرار است کلیدهای OAuth را ایجاد کند باید دسترسی «Full» به همان Property داشته باشد تا API امکان خواندن داده‌ها را داشته باشد.

2. **ایجاد پروژه و فعال‌سازی API**
   - به [Google Cloud Console](https://console.cloud.google.com/) بروید و یک پروژه جدید بسازید یا پروژه‌ی موجود را انتخاب کنید.
   - از منوی «APIs & Services» گزینه «Library» را باز کنید، جستجو نمایید و **Search Console API** را برای پروژه فعال کنید.

3. **پیکربندی صفحه رضایت OAuth**
   - در بخش «OAuth consent screen» نوع برنامه را روی «External» قرار دهید (در صورت استفاده سازمانی می‌توانید Internal انتخاب کنید).
   - نام برنامه، دامنه‌های مجاز و ایمیل پشتیبانی را وارد کنید.
   - دامنه‌ای را که مالکیت آن را در سرچ کنسول تأیید کرده‌اید در قسمت «Authorized domains» اضافه کنید و تغییرات را ذخیره کنید.

4. **ساخت شناسه OAuth Client**
   - از مسیر «Credentials» روی «Create Credentials» و سپس «OAuth client ID» کلیک کنید.
   - نوع برنامه را «Web application» قرار دهید.
   - مقدار مناسب برای «Authorized redirect URIs» اضافه کنید. اگر قصد دارید از OAuth Playground برای تولید توکن استفاده کنید، مقدار `https://developers.google.com/oauthplayground` را اضافه کنید؛ در غیر این صورت آدرس دلخواهی که پاسخ OAuth را دریافت می‌کند (مثلاً یک اسکریپت موقت روی دامنه خودتان) را ثبت کنید.
   - پس از ساخت، مقادیر **Client ID** و **Client Secret** را یادداشت کنید؛ این مقادیر دقیقاً فیلدهای `sc_client_id` و `sc_client_secret` در پنل سامانه هستند.

5. **دریافت Refresh Token**
   - ساده‌ترین راه، استفاده از [OAuth 2.0 Playground](https://developers.google.com/oauthplayground/) است. در صفحه تنظیمات (چرخ‌دنده بالا)، گزینه «Use your own OAuth credentials» را فعال کنید و Client ID/Secret مرحله قبل را وارد نمایید.
   - در مرحله اول Playground، از فهرست API ها گزینه «Search Console API v1» را باز کنید و دامنه‌ی دسترسی `https://www.googleapis.com/auth/webmasters.readonly` را انتخاب کنید. سپس «Authorize APIs» را بزنید.
   - در صفحه ورود گوگل، با همان حسابی که دسترسی Full به Property دارد وارد شوید و اجازه‌های خواسته‌شده را تأیید کنید. پس از بازگشت به Playground دکمه «Exchange authorization code for tokens» را بزنید.
   - مقدار `Refresh token` تولیدشده را کپی کنید؛ این مقدار باید در فیلد `sc_refresh_token` ذخیره شود. در صورت نیاز می‌توانید از همین صفحه تست «Refresh access token» را بزنید تا مطمئن شوید توکن معتبر است.

6. **ذخیره مقادیر در سامانه**
   - از منوی سامانه وارد بخش «تنظیمات API» شوید.
   - فیلدهای «Client ID»، «Client Secret»، «آدرس Property در Search Console» (برای مثال `https://example.com/` یا `sc-domain:example.com`) و «Refresh Token» را با مقادیر به‌دست‌آمده پر کنید.
   - بر روی «ذخیره» کلیک کنید. مقادیر در جدول تنظیمات داخلی ذخیره می‌شوند و فرایندهای زمان‌بندی‌شده از آن‌ها برای دریافت Access Token و خواندن گزارش‌ها استفاده می‌کنند.

7. **تست و عیب‌یابی**
   - یک اجرای دستی برای فرایند «دریافت داده گوگل» از صفحه پردازش‌ها انجام دهید یا منتظر اجرای بعدی کران `cron.php` بمانید. در صورت موفقیت، جدول `search_console_daily` در پایگاه داده داخلی پر می‌شود.
   - اگر خطای «تنظیمات سرچ کنسول ناقص است» دریافت کردید، بررسی کنید که هر چهار مقدار (`sc_client_id`, `sc_client_secret`, `sc_refresh_token`, `sc_site`) در تنظیمات ذخیره شده باشند.
   - برای خطاهای مربوط به توکن، یک‌بار دیگر در OAuth Playground گزینه «Refresh access token» را اجرا کنید؛ در صورت خطای `invalid_grant`، معمولاً توکن قدیمی شده و باید فرآیند دریافت Refresh Token تکرار شود.

## امنیت و نگه‌داری

- به‌روزرسانی منظم وابستگی‌ها با اجرای `composer update` (پس از گرفتن پشتیبان از فایل‌ها و پایگاه داده).
- گرفتن نسخه پشتیبان از فایل‌های پیکربندی امن و پایگاه داده داخلی.
- استفاده از HTTPS برای پنل مدیریتی و محدود کردن دسترسی به آی‌پی‌های مجاز.
- بررسی دوره‌ای لاگ‌ها (`chatgpt.log`, `msw_debug.log`, لاگ‌های وب‌سرور) برای تشخیص خطاهای احتمالی.

## مهاجرت بین محیط‌ها

1. نسخه پشتیبان از پایگاه‌های داده و فایل‌های پیکربندی تهیه کنید.
2. مخزن را در محیط جدید استقرار دهید و وابستگی‌ها را نصب کنید.
3. فایل‌های پیکربندی را بازگردانی کرده و در صورت تفاوت دامنه/مسیر، مقادیر را اصلاح کنید.
4. سرویس‌های پس‌زمینه و کران را مطابق با محیط جدید راه‌اندازی کنید.
