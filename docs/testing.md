# راهنمای تست و پوشش کیفیت

این سند توضیح می‌دهد چگونه تست‌های واحد پروژه اجرا می‌شوند، چه ماژول‌هایی تحت پوشش تست قرار گرفته‌اند و چگونه می‌توان تست‌های جدید اضافه کرد.

## پیش‌نیازها

1. **PHP 8.1 یا بالاتر** با افزونه‌های `curl` و `openssl` فعال.
2. **Composer** برای مدیریت وابستگی‌ها.
3. دسترسی به اینترنت برای نصب بسته `phpunit/phpunit` (در صورت عدم وجود کش داخلی).

> **نکته:** در محیط‌های محدود شبکه (مانند بعضی سرورهای سازمانی) ممکن است اجرای `composer install` به دلیل محدودیت دسترسی به Packagist با خطا مواجه شود. در این صورت باید مخزن آینه یا کش داخلی معرفی شود.

## نصب وابستگی‌های تست

```bash
composer install
```

پس از نصب، ابزار PHPUnit از مسیر `vendor/bin/phpunit` در دسترس خواهد بود. همچنین اسکریپت میانبر `composer test` برای اجرای تست‌ها تعریف شده است.

## اجرای تست‌ها

```bash
# اجرای کامل تست‌ها
composer test

# یا به صورت مستقیم
./vendor/bin/phpunit
```

## ساختار تست‌ها

```
/tests
├── ChatGPTManagerTest.php   # تست‌های مرتبط با رمزنگاری تنظیمات و مدیریت اتصال به API
└── SEOAnalyzerTest.php      # تست‌های مربوط به تحلیل سئو و پیشنهادهای متا/عنوان
```

- فایل پیکربندی PHPUnit در سطح ریشه مخزن با نام `phpunit.xml` قرار دارد و به صورت خودکار autoload را از `vendor/autoload.php` انجام می‌دهد.
- کلاس‌ها از طریق autoload نوع Classmap (مقداردهی شده در `composer.json`) در دسترس قرار می‌گیرند.

## سناریوهای پوشش داده شده

- **ChatGPTManager**
  - ذخیره امن کلید API با رمزنگاری و بارگذاری مجدد آن.
  - مدیریت خطای نبود کلید هنگام تست اتصال.
  - رفتار استثنا هنگام تلاش برای شروع گفتگو بدون کلید معتبر.
- **SEOAnalyzer**
  - محاسبه امتیاز بالا برای محتوای بهینه‌سازی شده و خالی بودن هشدارها.
  - تولید هشدارهای دقیق برای محتوای ضعیف (طول عنوان، متا، ساختار هدینگ، لینک‌ها و خوانایی).
  - اطمینان از اینکه پیشنهاد عنوان و متا شامل نام محصول است و طول متا در بازه توصیه‌شده قرار می‌گیرد.

## افزودن تست جدید

1. فایل تست جدیدی در پوشه `tests` ایجاد کنید (نام فایل با پسوند `Test.php`).
2. کلاس تست باید از `PHPUnit\Framework\TestCase` ارث‌بری کند.
3. در صورت نیاز به داده‌های نمونه، از متد `setUp()`/`tearDown()` برای آماده‌سازی و پاک‌سازی استفاده کنید.
4. در انتها `composer test` را اجرا کنید تا از موفقیت‌آمیز بودن تست اطمینان حاصل شود.

## گزارش‌گیری و یکپارچه‌سازی

- می‌توان با افزودن گزینه `--coverage-html build/coverage` به دستور PHPUnit، گزارش پوشش کد ایجاد کرد (نیازمند فعال بودن افزونه Xdebug).
- پیشنهاد می‌شود اجرای تست‌ها به عنوان بخشی از فرآیند CI/CD پروژه تعریف شود.
